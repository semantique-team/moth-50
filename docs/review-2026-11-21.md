# Review 2026-11-21 — selection target, E-004 B, the E-011 diagnosis and the final run

> Written 2026-11-21 after E-010, E-011, E-012 and E-004 arm B landed on `main`
> (`4600fc5`). **Status: proposed.** Nothing here moves a pre-registered gate or
> a decision: each step below needs its own pre-registration in
> `experiments/next-experiments.md` (or a dated E-002 amendment) before it runs.
> The numbers are recomputed from committed artifacts; the snippet at the end
> reproduces them.

## 1. Summary

- **Engineering and protocol discipline are sound.** E-012 and E-004 B were
  lossless where they claimed to be, pins and errata work, and the
  pre-registered rules were applied as written.
- **The LM is the lever, not acoustic depth or schedule.** E-004 B (unpruned
  E-034 LM, no acoustic change) moved S1-dev by −2.43 pp WER / +4.30 pp ETA;
  E-011 (2.5× more training) moved S1-dev WER by ~0.
- **The weak point is selection.** dev-macro ranks and S1-dev can only veto.
  E-009, E-010 and E-011 were ranked on dev-macro and did not reach the product;
  a mixed calibration set (E-017) is still missing.
- **B's S1-dev gain is ~5× its T-600 gain** (acronym ETA +16.8 vs +3.3 pp).
  Check the S1-dev scripts against the LM corpus before quoting the S1-dev
  number as product evidence (P2).
- **E-004 C no longer fits** next to the E-034 LM (~52.3 MB). **D only makes sense
  LM-first:** a larger LM read on base+6 before any base+4 training (P9).
- **E-011 was judged with A3, not the product LM.** Re-read it with E-034 before
  deciding the final-run recipe (P6); its ETA loss looks recipe-level (§4).

## 2. Finding 1 — the ranking set does not represent the product

| Decision | Ranked on | Product outcome |
|---|---|---|
| E-009 decoder 0.45 / 2.0 | dev-macro (−0.28 pp) | S1-dev veto: +0.58 pp WER, −1.12 pp ETA |
| E-010 `lr_encoder = 1e-4` | greedy dev-macro at 4k (−1.07 pp) | never read on a mixed set; fed E-011 |
| E-011 40k steps + EMA | dev-macro (−1.70 / −1.76 pp) | S1-dev WER tie; ETA −2.20 / −1.37 pp, seed 0 vetoed |
| E-004 B, unpruned E-034 LM | dev-macro as guard (−0.63 pp) | S1-dev −2.43 / +4.30 pp, T-600 −0.52 / +1.15 pp: adopted |

dev-macro is monolingual read audiobooks (MLS-IT, LS-EN with native English).
It has no code-switching, no Italian-accented English and no term list, so it
cannot see ETA. With S1-dev reserved as a one-shot veto, a change that helps the
product but not dev-macro is never proposed, and a change that helps dev-macro
at the product's expense is (correctly) vetoed. E-004 B passed because it
targeted the product's errors directly (term coverage) and every set moved the
same way; that will not hold for most changes.

The fix is already written: **E-017**, a mixed calibration set separate from the
S1-dev gate, in the unmerged branch `docs/frontier-teachers-plan` (P1, P5).
E-002 §1 originally gave S1-dev the role "primary product dev and checkpoint
selection"; the §6 amendment turned it into a veto. S1-dev has now been read for
E-005, E-009, E-011 and E-004, so its value as a held-out set is shrinking.

  same templates) are in that corpus. Either way, the S1-dev number overstates
  what a new speaker or new text will see; the T-600 number (−0.52 / +1.15) is
  the conservative estimate. P2 checks it.

## 4. Finding 3 — the E-011 ETA loss is likely recipe-level

These readouts use **A3**, not the product LM. S1-dev per category, WER / ETA in
%, FP32 (`runs/E-005/s1-dev-a3-fp32.json`, `runs/E-011/s1-dev-s{0,1}.json`):

| Category | E-005 | E-011 s0 | E-011 s1 |
|---|---:|---:|---:|
| `control_en` | 17.06 / 85.29 | **19.29 / 83.76** | **19.41 / 82.94** |
| `switch` | 12.88 / 81.63 | **14.95 / 74.60** | **13.92 / 79.37** |
| `single_word` | 6.46 / 86.61 | 7.40 / 82.14 | 6.46 / 87.50 |
| `phrase` | 14.78 / 64.26 | 13.98 / 63.23 | 13.19 / 66.67 |
| `brand` | 19.79 / 47.29 | 20.14 / 46.51 | 21.70 / 43.41 |
| `acronym` | 22.32 / 29.20 | 20.13 / 31.86 | 21.48 / 28.32 |
| `italianized` | 12.04 / 71.43 | 9.96 / 75.89 | 10.25 / 71.43 |
| `control_it` | 8.48 / — | 6.36 / — | 8.13 / — |

dev-macro per language (`runs/E-005/readout-a3.json`,
`runs/E-011/readout-s{0,1}.json`): MLS-IT 23.35 → 20.94 / 20.87 %, LS-EN
11.77 → 10.78 / 10.72 %.

Native English and Italian improve, while S1's Italian-accented English
(`control_en`, +2.2 / +2.4 pp WER) and code-switch ETA (`switch`) get worse **on
both seeds**. The category samples are small (`control_en` is 119 clips, 850
words), so this is a consistent direction, not a proven effect: the pattern of a
recipe that trades accent and code-switch robustness for monolingual fit.

E-011 changed three things against E-005, so the cause is not isolated:

- **H1 — encoder LR.** `lr_encoder = 1e-4` for ~3 epochs may erode the
  pretrained Whisper encoder's robustness to accented English. The LR was
  chosen in E-010 on dev-macro only.
- **H2 — gold over-exposure.** Gold ×50 is 70,650 of 273,714 clips per epoch
  (25.8 % of the clips, ~8 % of the audio). At 2.97 epochs each gold sentence is
  seen ~149 times (E-005: ~59). A 39 M model can memorize 1,413 sentences; E-006
  arm 2 already flags this.
- **H3 — length and EMA** themselves.

With E-034 carrying more of the term load, the E-011 picture may change: that is
P6, before any ablation.

## 5. Finding 4 — seed noise is large and the veto does not model it

S1-dev ETA counts 2,048 English terms (A3 readouts).

| Pair | Newly wrong | Newly right | Net |
|---|---:|---:|---:|
| E-005 → E-011 s0 | 164 | 119 | −45 (−2.20 pp) |
| E-005 → E-011 s1 | 134 | 106 | −28 (−1.37 pp) |
| E-011 s0 → s1 (same recipe) | 118 | 135 | +17 (+0.83 pp) |
| E-005 FP32 → INT8 | 11 | 15 | +4 (+0.20 pp) |

Only 69 newly wrong and 66 newly right terms are shared by both seeds: each
seed loses different terms, which fits a distribution shift and also seed noise.

- Two runs of the **same** recipe disagree on 253 terms; the recipe change
  disagrees on 283. The paired bootstrap resamples utterances only; it does not
  include training-seed variance, and the control (E-005) has a single seed.
- A recipe experiment runs at least four one-sided tests (2 seeds × WER/ETA).
  For a candidate equal to the control, utterance noise alone fails at least one
  about 10 % of the time (1 − 0.975⁴), before seed noise. The rule leans toward
  the status quo.
- **The E-011 verdict under A3 stands.** The proposal in P11 is for future gates.

## 6. Finding 5 — what is left of E-004 C and D

The package is now **49,210,224 B** (789,776 B of room).

- **C (base+7) does not fit with E-034.** base+7 + packed A3 was estimated at
  47.88 MB; swapping in E-034 adds 4.44 MB, so **~52.3 MB**. base+7 would need an
  LM of at most ~5.4 MB, i.e. a pruned E-034 that gives back part of B's gain,
  for an expected ≤ 0.6 pp dev-macro from depth (E-003: 11.2, 2.2, 1.3 pp per two
  blocks from +0 to +6) that may not reach the product (E-011). **Do not run C.**
- **D (base+4 + a larger LM) is now an LM question.** base+4 frees ~6.4 MB, room
  for an LM of ~15 MB. E-034 is already unpruned at order 3 for its corpus, so a
  larger LM needs more text (E-020) or a higher order (a new MOTHLMB format, JS
  reader and decoder change). Acoustically, base+4 is 1.01 pp worse than base+6 at
  4k steps and 1e-4 (33.40 vs 32.39 %). D's other advantage is speed, and
  1-thread RTFx is unmeasured (E-016).

**Other gaps:** FLEURS is still unread; `run.json` does not record which Mac ran
the job; only `ckpt_best.pt` / `ckpt_last.pt` survive a run, so E-011's
trajectory over steps cannot be read after the fact.

### P10 — One recipe ablation, only if P6 fails

### P11 — Final run (if still needed after P6)

- **Recipe:** P10's winner (E-005's if none wins), base+6, pre-registered
  before training. Depth is fixed by the budget (§6).
- **Seeds:** 3 (2 minimum).
- **Checkpoints:** keep a weights-only checkpoint at every eval
  (`ckpt_step{N}.pt`, EMA weights; ~157 MB each at 39.3 M FP32 parameters,
  ~1.6 GB per seed). Needs a small trainer option.
- **Provenance:** record the machine (hostname, chip) in `run.json`.
- **Selection:** checkpoint and recipe on the calibration set; never choose a
  seed on S1-dev.
- **Gate (proposed amendment, future gates only):** compare seed means; the
  no-regression test uses per-utterance errors averaged over seeds; report every
  seed. If gated against E-005, consider a second E-005 seed (6.7 h) so that the
  control has seed variance too.
- Then INT8 cost, package, browser and FLEURS; T only as a declared repeated

## 8. Where the training hours go

Before E-004 the plan was C long (2 × ~17 h), D (2 × ~15 h) and a final run
(2–3 × ~16 h): roughly 80–110 h of M5 Pro time. After B, C is out, D waits for
an LM result, and P6 may make the final run unnecessary: the committed MPS time
is now **0–65 h**, decided by readouts that take minutes.

B confirms what E-011 suggested: the product is limited by what the decoder and
the data know about code-switching and terms, not by acoustic capacity. The
larger levers are LM text and order (P8, P9, E-020) and data aimed at the
product errors: accented English and code-switching (E-019 arm B, unscripted
S1; Granary/VoxPopuli pseudo-labels), acronyms, brands and elisions (E-021).
With two Macs, one can run a data arm (a fine-tune from E-005 against a
same-length control) while the other runs P6–P10.

## Reproduce §3–§5

From the repository root, Python 3 standard library only:

```python
import json
from collections import Counter

def load(p):
    return json.load(open(p, encoding="utf-8"))

def errs(d):
    return Counter((e["id"], e["term"]) for e in d["metrics"]["eta_errors"])

def cats(*runs):
    for c in runs[0]["metrics"]["category"]:
        print(c, [(round(r["metrics"]["category"][c]["wer"] * 100, 2),
                   r["metrics"]["category"][c]["eta"]) for r in runs])

# §3 E-004 B: A3 -> E-034 on S1-dev and T-600 (INT8)
a3, b = load("runs/E-005/s1-dev-a3-int8.json"), load("runs/E-004/s1-dev-e034-int8.json")
ta, tb = load("runs/E-004/t600-a3-int8.json"), load("runs/E-004/t600-e034-int8.json")
cats(a3, b)
cats(ta, tb)
for s in ta["metrics"]["speaker"]:
    print(s, ta["metrics"]["speaker"][s]["wer"], tb["metrics"]["speaker"][s]["wer"])
print("S1-dev ETA newly right", sum((errs(a3) - errs(b)).values()),
      "newly wrong", sum((errs(b) - errs(a3)).values()))

# §4-§5 E-011 vs E-005 with A3 (FP32)
runs = {
    "E005": load("runs/E-005/s1-dev-a3-fp32.json"),
    "E005i": a3,
    "s0": load("runs/E-011/s1-dev-s0.json"),
    "s1": load("runs/E-011/s1-dev-s1.json"),
}
cats(runs["E005"], runs["s0"], runs["s1"])
E = {k: errs(v) for k, v in runs.items()}
for x, y in [("E005", "s0"), ("E005", "s1"), ("s0", "s1"), ("E005", "E005i")]:
    print(x, "->", y, "newly wrong", sum((E[y] - E[x]).values()),
          "newly right", sum((E[x] - E[y]).values()))
print("shared newly wrong", sum(((E["s0"] - E["E005"]) & (E["s1"] - E["E005"])).values()))
print("shared newly right", sum(((E["E005"] - E["s0"]) & (E["E005"] - E["s1"])).values()))
for p in ["runs/E-005/readout-a3.json", "runs/E-011/readout-s0.json",
          "runs/E-011/readout-s1.json"]:
    print(p, {k: round(v["wer"] * 100, 2) for k, v in load(p)["sets"].items()})
```
